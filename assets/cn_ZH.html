claude-code·queue
English

排队，不插队。

Claude Code 的消息队列。忙时输入 /queue …，消息会先等候——本轮跑完后才执行，而不是在下一个 tool-call 边界被插进去。

安装

$ git clone https://github.com/jinhuang712/claude-code-queue \
    ~/.claude/skills/queue
# 重启 Claude Code — 就有了裸 /queue
/queue then run the tests and fix failures
… Claude 继续干活，不受打扰 …
… 本轮结束 …
/queue then run the tests and fix failures
✓ auto-started

为什么

按回车，不该把当前任务带偏。

Claude Code 忙时你发的普通消息会在下一个 tool-call 边界被插进去——它会打断、带偏正在跑的任务。但对已注册的 slash command，Claude Code 原生就会等到整轮结束才投递。claude-code-queue 做的只是把 /queue 注册成一条命令：排队由原生调度器完成，命令正文则让 Claude 在你离开时也能把延后的请求稳妥跑完。

行为

排队的消息会怎么处理

忙时 → 等候区

当前轮不会被打断。本轮结束后自动 pop 并接手执行。

FIFO，一轮一条

多条按入队顺序排，一轮一条，在同一会话内——不会被别的会话抢走。

真实 prompt 抢占

忙时发的普通（不带 /queue）请求，永远排在排队项前面。

闲时 → 立即

没有在跑的任务，直接当作普通请求处理。

用法示例

怎么用

忙时排队一个后续任务

Claude 正忙。把下一个任务排进去，不打断：

/queue then run the test suite and fix anything that breaks
# 原生暂存；本轮结束后自动执行

排多条（FIFO，一轮一条）

/queue update the README with the new flag
/queue commit and push

真实 prompt 抢占

普通请求排在排队项前面：

/queue polish the docs later
actually fix this blocking bug first   # 这个先跑

没有 hook、没有守护进程、没有存储——只有一个命令定义。按 ↑ 可编辑排队中的消息（原生功能）。原理详见 仓库。
