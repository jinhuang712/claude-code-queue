claude-code·queue
中文

queue, not interrupt.

A prompt queue for Claude Code. Type /queue … while Claude is busy and the message waits — it runs after the current turn, instead of being injected at the next tool-call boundary.

Install

$ curl -fsSL \
  https://jinhuang712.github.io/claude-code-queue/install.sh \
  | bash
# restart Claude Code — you now have a bare /queue
claude-code

Why

Pressing Enter mid-turn shouldn't derail the turn.

A plain message sent while Claude Code is mid-turn is injected at the next tool-call boundary — it interrupts and redirects the running task. But Claude Code holds a recognized slash command until the whole turn ends. claude-code-queue simply registers /queue as one: the native scheduler does the queueing, and the command body tells Claude to run the deferred request unattended.

Behavior

How a queued message is treated

Busy → waiting area

The current turn is not interrupted. The message is popped and auto-started when it finishes.

FIFO, one per turn

Multiple items drain in order, one turn each, in the same session — never stolen by another session.

Real prompts preempt

A normal (non-/queue) prompt submitted while busy always runs before deferred items.

Idle → immediate

Nothing to wait behind — handled at once as a normal turn.

Before & after

Send it plainly, or queue it

Same follow-up, typed while Claude is mid-turn. A plain message cuts in at the next tool call; /queue waits for the turn to finish.

Without /queue — it interrupts
claude-code
❯ refactor the auth module
✻ Working… (6s · esc to interrupt)
⏺ Edit src/auth/session.ts
❯ also update the README
↳ injected at the next tool call — the refactor gets redirected
With /queue — it waits
claude-code
❯ refactor the auth module
✻ Working… (6s · esc to interrupt)
⏺ Edit src/auth/session.ts
❯ /queue also update the README
✓ auth module refactored
❯ also update the README
FIFO — line up several, one per turn
claude-code
✻ Working… (3s · esc to interrupt)
❯ /queue update the README with the new flag
❯ /queue commit and push
❯ Press up to edit queued messages
— they drain in order, one per turn —

No hooks, no daemon, no storage — just a command definition. Press ↑ to edit what's queued (native). See the repo for how it works.
